## Variables

Copiar `.env.example` a `.env.local` sólo en una copia nueva; no sobrescribir la configuración existente.

| Variable               | Uso                                                                      |
| ---------------------- | ------------------------------------------------------------------------ |
| `R2_ACCOUNT_ID`        | Cuenta de Cloudflare; el script construye el endpoint S3 predeterminado. |
| `R2_BUCKET_NAME`       | Nombre literal del bucket, sin `buckets/`.                               |
| `R2_ACCESS_KEY_ID`     | Credencial S3 de R2 con Object Read & Write para este bucket.            |
| `R2_SECRET_ACCESS_KEY` | Secreto S3, exclusivamente local/servidor.                               |
| `R2_PUBLIC_BASE_URL`   | Origen HTTPS público sin nombre de bucket ni ruta.                       |

SDK AWS S3 para JavaScript v3, región `auto`. Endpoint: `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`. Esta implementación corresponde a un bucket de jurisdicción predeterminada; un bucket EU/US restringido requiere adaptar el endpoint antes de usarlo.

Nunca usar prefijos NEXT_PUBLIC para las credenciales. El sitio recibe sólo las URL de recursos preparados. No hay endpoint público de subida. En el alojamiento del sitio sólo hace falta `R2_PUBLIC_BASE_URL` para seleccionar las URL ya publicadas; las credenciales de escritura no se necesitan para servir el portafolio.

## Flujo reproducible (PowerShell, Node 24, npm)

Desde la raíz del proyecto:

```powershell
npm run media:inventory
npm run media:review
# Revisar las planchas y media/review-decisions.json.
# Editar media/selections.json sólo con contenido autorizado.
npm run media:prepare
npm run media:dry-run
npm run media:upload
npm run build
npm run start
```

`ffprobe` y `ffmpeg` deben estar en PATH. Sharp y los paquetes S3 están fijados en package-lock.json como herramientas de desarrollo. No se requieren para la reproducción en el navegador.

Originales esperados en `media/source/` con las siete carpetas. Para otro directorio:

```powershell
$env:MEDIA_SOURCE_ROOT = 'D:\recursos-portafolio'
npm run media:inventory
```

El inventario enumera recursivamente archivos normales, no sigue enlaces simbólicos, registra peso, hash, dimensiones, duración y códec, y documenta errores por archivo. La revisión genera cinco candidatos por video, nunca elige automáticamente el primero. La preparación sólo procesa selecciones con `privacy: approved`; conserva fuentes y crea WebP hasta 1920 px y MP4 H.264 sin audio, con faststart. Los fotogramas finales se extraen desde el original a resolución completa, no desde las miniaturas de revisión.

## Subidas, errores y caché

- Claves: `projects/{slug}/{image|video}/{nombre}-{sha256-parcial}.{ext}`. El hash se calcula sobre el derivado final; un cambio de contenido genera otra URL.
- Cada subida recalcula el hash local y compara metadatos SHA-256 remotos antes de escribir. Un 403 de lectura remota es un error, no se interpreta como un archivo ausente.
- El SDK hace hasta tres intentos. Upload utiliza streams, partes de 8 MiB y dos partes concurrentes; no carga un video completo en memoria. Aborta partes ante fallo; no borra objetos existentes.
- Content-Type explícito y `Cache-Control: public, max-age=31536000, immutable` para recursos versionados.
- HEAD público comprueba disponibilidad. Sólo al terminar todos los objetos se escribe `lib/generated/media-urls.json`. Un fallo mantiene el mapa anterior; los objetos ya subidos se reutilizan en el siguiente intento.
- `--dry-run` no necesita credenciales ni hace solicitudes de red. Genera el plan en `reports/media/dry-run.json`.

El navegador tiene respaldo local de cada recurso. La imagen cambia a su copia local si el recurso remoto falla; el video ofrece la misma recuperación. Sin `R2_PUBLIC_BASE_URL`, el sitio selecciona directamente los recursos locales. Una URL nueva no se usa hasta que se haya generado un mapa validado. Reiniciar/reconstruir Next después de cambiar el origen: next/image autoriza sólo ese host y `/projects/**`.

## Dominio y CORS

Cuando tengas dominio: R2 → bucket → Settings → Custom Domains → Add. Conectar un subdominio de una zona de la misma cuenta; esperar estado Active. Actualizar únicamente `R2_PUBLIC_BASE_URL`, ejecutar `media:upload` y reconstruir. No apuntar un CNAME a r2.dev ni usar el endpoint S3 como CDN.

El uso actual de imágenes mediante next/image y video nativo no requiere habilitar CORS. Si se añade fetch desde el navegador o canvas, configurar en R2 una regla específica para el origen del portafolio, métodos GET/HEAD y las cabeceras realmente necesarias; no dar permisos de escritura al navegador.

## Agregar otro proyecto

1. Añadir el slug a `scripts/media.mjs`, sus originales a `media/source/<slug>` y revisar inventario/candidatos.
2. Añadir selecciones aprobadas, incluyendo exactamente una portada y un poster para cada video.
3. Añadir contenido en `lib/projects.ts`, sin editar componentes. Campos opcionales de rol y fecha sólo cuando estén documentados.
4. Preparar, simular, subir y reconstruir. Las rutas y sitemap se generan desde el catálogo.

Pendiente de producción: dominio personalizado, autorización comercial de marcas/recursos de terceros que corresponda y pruebas en dispositivos físicos/lector de pantalla. No faltan credenciales para el bucket conectado.

Documentación oficial: [autenticación R2](https://developers.cloudflare.com/r2/api/tokens/) y [acceso público](https://developers.cloudflare.com/r2/buckets/public-buckets/).
